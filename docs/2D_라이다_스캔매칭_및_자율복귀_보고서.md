## 1. 배경 및 역할 분담 구조

### 1.1 라이다(LDS-01) 센서 및 SLAM 연산의 역할 분담
본 프로젝트의 전체 아키텍처에서 2D 라이다 센서는 **하드웨어 구동·온보드 생존 제어**와 **관제용 SLAM 연산**이 물리적으로 분리되어 동작한다.

| 구분 | 로봇 본체 (Raspberry Pi 4) | 관제국 (Host PC - WSL2) |
| :--- | :--- | :--- |
| **담당 기능** | LDS-01 하드웨어 제어, 모터 구동, 온보드 자율 복귀 | Cartographer / `slam_toolbox` 2D SLAM, RViz2 관제, 비전·음성 AI |
| **실행 노드** | `turtlebot3_bringup/robot.launch.py` (`hlds_laser`), `recovery_controller` | `turtlebot3_cartographer/cartographer.launch.py`, `host_ai_pipeline` |
| **발행/구독 토픽** | `/scan` (`sensor_msgs/msg/LaserScan`, 360점, ~5 Hz) | `/map` (`nav_msgs/msg/OccupancyGrid`), TF 변환 |
| **핵심 활용** | Layer-0 잡음 제거, `RollingLocalGrid + 2D A*` 우회, `ContextRLStudent` ONNX, 2D ICP 오차 보정, 긴급 제동 | 실시간 2D 지도 생성, 조난자 탐지(YOLO26n), `semantic_map_node` 시맨틱 마커·오버레이 생성 |

### 1.2 통신 두절 시 온보드 자율 복귀가 필요한 이유
Wi-Fi 통신이 끊겼을 때(Heartbeat 3.0초 타임아웃) 로봇이 Host PC의 SLAM 지도를 기다리지 않고 온보드 연산만으로 복귀하는 이유는 **시스템 자립성(Off-Grid Standalone)** 때문이다.

1. **통신 단절 시 SLAM 지도 수신 불가:** 연결이 끊기면 Host PC의 Cartographer 지도 및 원격 조종 명령을 받을 수 없다.
2. **RPi 4 온보드 연산 한계:** Raspberry Pi 4 단독으로 무거운 전역 SLAM과 Nav2 전체 스택을 상시 구동하기에는 CPU와 메모리 여유가 제한적이다.
3. **계층형 온보드 생존성:** 탐색 중 `0.30 m` 전진 또는 `25°` 회전 시마다 경유지 좌표와 스캔 점군을 LIFO 스택에 저장해 두고, 단절 시 온보드에서 즉시 역추종(`A*` 우회 + `Context-RL ONNX` + `2D ICP` 보정)을 수행하는 구조가 가장 확실한 생존책이다.

## 2. 설계 의사결정: 단순 회피 vs 스캔 매칭 → 계층형 융합

초기 프로토타입 단계부터 현재 Phase 2-B까지의 아키텍처 진화 과정은 다음과 같다.

```text
[초기 고민: 단순 APF 회피만 쓸 경우]
장애물 발생 ─▶ 급격한 회피 회전 ─▶ 바퀴 헛돎(Wheel Slip) 누적 ─▶ 오도메트리 궤적 붕괴 ─▶ 기지 복귀 실패

[1차 해결 (2026-11-10): 2D 라이다 스캔 매칭(ICP) 도입]
경유지별 스캔 저장 ─▶ 복귀 시 2D SVD ICP 매칭 ─▶ 바퀴 슬립 오차 상쇄 ─▶ 출발점 유효 시야 진입 ─▶ ArUco 도킹

[현재 구조 (Phase 2-B, 2026-11-15): 4계층 하이브리드 융합 (150회 99.33%)]
Layer-0 연기 잡음 제거 ─▶ RollingLocalGrid(2D A*) + Context-RL ONNX 우회 ─▶ 2D ICP 슬립 보정 ─▶ ArUco 도킹
```

- **왜 2D 라이다 스캔 매칭(ICP)이 필수였는가:** 차동 구동 로봇의 휠 엔코더 사체 항법(Dead Reckoning)은 회전 시 방위각(Yaw) 오차가 누적되어 `5~10 m`만 주행해도 실제 원점과 수십 cm 이상 빗나간다. 특히 동적 낙석을 피하느라 회전이 잦아지면 오차가 급격히 커지며, ArUco 카메라의 유효 시야(FOV 약 60°, 인식 거리 ~1 m) 안으로 들어가지 못하면 정밀 도킹 자체가 불가능하다.
- **현재의 통합 해법:** `RollingLocalGrid(0.04 m) + 2D A*` 및 `ContextRLStudent ONNX`로 복귀 중 새로 떨어진 낙석과 움직이는 장애물을 능동 우회하면서도, 경유지 `45 cm` 이내 접근 시마다 **2D SVD ICP**로 바퀴 슬립 오차를 주기적으로 소거하여 "우회 능력"과 "정밀 위치 유지"를 동시에 달성했다.

## 4. 2D 라이다 스캔 매칭(ICP) 및 Phase 2-B 고도화 설계

### 4.1 SVD 기반 2D ICP 수학적 모델링
로봇 프레임에서 유효 거리 내의 2D 레이저 점군을 직교 좌표로 변환한다.

$$p_i = \begin{bmatrix} r_i \cos\alpha_i \\ r_i \sin\alpha_i \end{bmatrix}$$

기준 경유지의 저장 점군을 $P_{\mathrm{ref}}$, 현재 로봇의 스캔 점군을 $P_{\mathrm{cur}}$라 할 때, 2차원 강체 변환 $[R \mid t]$는 다음 오차를 최소화한다.

$$\min_{R, t} \sum_{i} \| R p_{\mathrm{cur}, i} + t - p_{\mathrm{ref}, \mathrm{match}(i)} \|^2$$

1. **오도메트리 초기 추정 (Warm Start):** 현재 보정 좌표와 목표 경유지 좌표의 상대 변위 `(dx_guess, dy_guess, dth_guess)`를 초기값으로 주어 빠른 수렴을 유도한다 (`max_iters=15`).
2. **SVD 기반 최적 회전 계산:** 인라이어 점군의 중심점을 맞춘 뒤 공분산 행렬 $H = (p_{\mathrm{src}} - c_{\mathrm{src}})^T (p_{\mathrm{dst}} - c_{\mathrm{dst}})$를 특이값 분해(`np.linalg.svd`)해 최적 회전 행렬 $R$과 평행이동 $t$를 3.5 ms 이내에 구한다.
3. **이상치 제거 (Outlier Rejection):** 최근접 거리 `inlier_thresh = 0.35 m`를 초과하는 점(새로 생긴 낙석이나 이동 장애물)은 매칭에서 자동 제외하며, 인라이어가 `min_inliers = 15`개 미만이면 보정을 건너뛰어 오보정을 방지한다.

### 4.2 지속형 SE(2) 보정 오프셋 유지 (`T_corr`)
초기 구현에서는 보정된 좌표를 `current_x, current_y`에 1회 대입했다가 다음 `/odom` 콜백 수신 시 덮어써지는 한계가 있었다. 이를 해결하기 위해 현재 `recovery_controller.py`는 측정 포즈 $T_{\mathrm{meas}}$와 원시 오도메트리 $T_{\mathrm{raw}}$ 간의 상대 변환 $T_{\mathrm{corr}} = T_{\mathrm{meas}} \cdot T_{\mathrm{raw}}^{-1}$를 상보필터($\alpha = 0.40$)로 누적 유지하여, 이후 수신되는 모든 `/odom` 메시지에 보정 오프셋이 지속적으로 적용되도록 개선되었다.

### 4.3 Phase 2-B Layer-0 연기 스파이크 필터 & Open-Ray Carving
15대 재난 시나리오 150회 벤치마크에서 확인된 **연기·분진 난반사(`#15`)** 와 **이동 장애물 잔상(`#14`)** 문제를 해결하기 위해 `2D 라이다` 처리 전단에 두 가지 필터를 추가했다.
- **이웃 각도 군집 검사 필터 (`_despike_lidar_ranges`):** `cb_scan` 수신 직후 `±3°` 7-광선 창 내에서 거리 편차가 `0.24 m` 미만인 이웃이 `3개` 미만인 `2.20 m` 이내 고립 스파이크(연기·분진 헛점)만 배경 75% 분위수(`bg_val`)로 치환한다. 실제 벽체와 낙석 윤곽은 그대로 보존된다 (`#15`: `0/10 → 10/10`).
- **Open-Ray Carving & 점군 분리:** `RollingLocalGrid` 갱신 시 열린 광선 경로의 점유 셀(`self.occ`)은 빠르게 소거(`carve_decay=0.25`)하되, 2D ICP용 정적 점군과 `observed_free` 신뢰도는 분리 보존한다 (`#14`: `0/10 → 10/10`).

### 4.4 Phase 3 구현 완료: 2D 라이다 + 단안 RGB 투영 퓨전
- Host PC 관제 노드([`semantic_map_node.py`](../src/disaster_recovery/disaster_recovery/semantic_map_node.py), [`semantic_mapper_core.py`](../src/disaster_recovery/disaster_recovery/semantic_mapper_core.py))에서는 추가 3D Depth 카메라 없이 **LDS-01 2D LiDAR(`/scan`) 점군을 단안 카메라 좌표계(`camera_rgb_optical_frame`)로 투영해 YOLO26n 바운딩 박스와 매칭**(선행 논문 수식 3 Y 오타 정정 · 270° CCW 역변환 · `+0.25 m` 전경 클러스터링)함으로써 조난자·저상 장애물의 3D 좌표를 추정하고 2D 시맨틱 맵에 마커로 영구 기록한다 ([상세 보고서](./차세대_고도화_시맨틱_SLAM_및_RL_재학습_계획.md)).
